# legalhold

法律保全感知的消息清退库（Go），由上层清理任务直接调用。

每个 `Cleaner` 实例处理一个邮箱的一轮清理。数据只保存在进程内，
模块只管理候选消息元数据（编号、发送时刻、到期时刻），
不保存正文或附件，也不执行文件删除。

## 特性

- 初始化时传入固定候选集，期间不新增或修改候选消息。
- 支持新增保全、解除保全和清退；每项保全有独立编号，
  即使区间完全相同也是两项独立保全，需逐个解除。
- 保全覆盖发送时刻处于 `[start, end)` 的所有尚存候选消息：
  包含区间起点，不包含终点。多项保全的区间可以重叠，
  解除其中一项不会误删另一项仍需保留的消息。
- 消息被任意一项有效保全覆盖就不能清退；最后一项保护解除后，
  已到期消息立即重新具备清退资格，未到期消息继续等待。
- 每次清退由调用方提供当前时刻（单调不减），返回并移除
  已到期（`ExpireAt <= now`）且未受保全的消息编号。
  到期时刻等于当前时刻即可清退。
- 清退结果是最终删除决定：同一消息不会再次返回，
  之后新增保全不追溯已清退的消息。

## 使用示例

```go
c := legalhold.NewCleaner([]legalhold.Message{
	{ID: 1, SentAt: 100, ExpireAt: 500},
	{ID: 2, SentAt: 200, ExpireAt: 900},
})

c.AddHold(10, 0, 300) // 案件一：保全 [0, 300)
c.AddHold(11, 0, 300) // 案件二：区间相同，仍是独立保全

c.Purge(600) // => []        两项保全都在，已到期的 1 也不能清退
c.RemoveHold(10)
c.Purge(600) // => []        案件二仍在保护
c.RemoveHold(11)
c.Purge(600) // => [1]       最后保护解除，已到期的 1 立即清退
c.Purge(900) // => [2]       2 到期后清退
```

## API

| 方法 | 说明 |
| --- | --- |
| `NewCleaner(candidates []Message) *Cleaner` | 以固定候选集创建实例 |
| `AddHold(id, start, end int64)` | 新增保全，覆盖 `SentAt ∈ [start, end)`；`id` 已存在则替换 |
| `RemoveHold(id int64)` | 解除指定保全；不存在则无效果 |
| `Purge(now int64) []int64` | 返回并移除已到期且未受保全的消息编号（升序） |

时间统一使用 UTC 整数秒。`Cleaner` 不是并发安全的，
调用方需按顺序串行调用。

